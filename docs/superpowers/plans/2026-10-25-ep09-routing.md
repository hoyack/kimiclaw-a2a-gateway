# EP09 Bot-Task Routing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Jira task labelled `owner_<bot>` gets claimed, handed to the bot over A2A, and answered with exactly one signed comment, even when n8n polls twice.

**Architecture:** One stdlib-only Python module (`routing/router.py`) holds all routing logic behind two tiny ports (Jira, Gateway). n8n only schedules: a per-bot Schedule Trigger runs `python3 -m routing.cli poll --bot <bot>`. Jira state (status + signed comments) is the only dedupe store, so there is no database to run.

**Tech Stack:** Python 3.11+ stdlib (`urllib`, `json`), pytest, n8n workflow JSON (files only).

**Spec:** `/workspace/a2aspec/bot-assignment.md` and Jira A2A-62..A2A-72 acceptance criteria.

## Global Constraints
- Pollers (`BOTS`): `rivet, tugboat, critic, bastion, cpo, cto`. Valid owners (`OWNERS`) add `brandon`, a human queue that is linted but never handed off. Exactly one `owner_` label per task.
- Queue JQL: `project=A2A AND labels=owner_<bot> AND status="To Do"`. Poll every ~5 min.
- Claim = transition To Do -> In Progress, then comment `[<bot>] picked up`.
- Every bot write is signed: comment body starts with `[<bot>]`.
- Failure comment: `[<bot>] failed: <error type>`. No payloads, no secrets in comments or logs.
- Secrets only from env (n8n credential / host env). Never in repo, tickets, or logs.
- Result comment leaves status alone (bot/owner moves it).

## Review Focus
1. n8n polls twice (sequential, and second poll while first handoff is in flight) -> one handoff, one result comment. Test: `test_double_poll_*`.
2. Gateway down / JSON-RPC error -> bounded retries, one failure comment, task moved to Blocked (`ROUTING_BLOCKED_STATUS`, default `Blocked`). A human moving it back to To Do re-queues it exactly once. Tests: `test_gateway_failure_*`, `test_failure_goes_to_blocked_status_from_env`, `test_manual_move_back_to_todo_requeues_exactly_once`.
3. Malformed issue (0 or 2 owner labels, empty summary) -> no handoff, no comment from the wrong bot. Test: `test_malformed_*`.
4. Crash between handoff and comment, re-run -> no second result comment. Test: `test_existing_result_not_duplicated`.
5. Agent returns `failed` state -> failure comment, not a result comment. Test: `test_agent_failed_state`.
